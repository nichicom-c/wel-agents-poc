# グリッドシステムの実装

出典: [デジタル庁デザインシステム — 基本デザイン / レイアウト](https://design.digital.go.jp/dads/foundations/layout/)。

## 公式ガイドラインの原則

- **カラム構成**: 12カラムを基本とし、1カラムレイアウトも代替として提供する。
- **ブレークポイント**: 単一のブレークポイントのみ。768px 未満を「モバイル・タブレット」、768px 以上を「デスクトップ」として2パターンのレイアウトを想定する。
- **マージン**: ページの余白を設定し、グリッド全体の配置を決める。ページ幅が狭くなった場合にも対応する(具体値の指定なし)。
- **ガター**: カラム間の余白。「原則として本文の文字サイズの2倍を確保する」。
- **カラム幅**: 「本文の文字サイズの整数倍」で設定する。

## 重要な前提: 公式は具体的な px 値・実装コードを公開していない

digital-go-jp の公式リポジトリ(`design-tokens` / `tailwind-theme-plugin` / `design-system-example-components-{html,react}`)を確認したが、**グリッド/レイアウト専用のトークンやコンポーネント実装は一切含まれていない**([tokens.md](./tokens.md) 参照)。上記の原則はガイドライン文章のみで、マージン幅・ガター幅・コンテナ最大幅の確定 px 値は本ドキュメント執筆時点で非公開。

したがって本スキルの実装は「文字サイズを基準にした相対値ルール」を Tailwind のユーティリティに翻訳したものであり、**確定仕様ではなく、原則に沿った実装パターンの提案**として扱うこと。プロジェクトの要件に応じてガター幅・マージン幅は調整してよい。

## 基準値の導出

- 本文標準の文字サイズは DADS タイポグラフィトークンの `text-std-16N-170`(`font-size: 1rem` = 16px)。→ **ガター = 1rem × 2 = 2rem(32px)** をデフォルト値とする。
- カラム幅は「文字サイズの整数倍」だが、12カラム CSS Grid で `1fr` 均等割りにする限り、この条件は自動的に満たされる(コンテナ幅が文字サイズの整数倍で設計されていれば、各カラム幅も整数倍になる)。カラム幅を px で固定するデザイン(帯グラフ的なレイアウトなど)を作る場合のみ、明示的に 16px の倍数へスナップさせる。

## Tailwind CSS v4 との整合: `md:` = 768px

Tailwind CSS v4 の既定ブレークポイントは `sm:640px` / `md:768px` / `lg:1024px` / `xl:1280px` / `2xl:1536px`。DADS の唯一のブレークポイント(768px)は Tailwind の **`md:`** と完全に一致する。カスタムブレークポイントを追加する必要はなく、`md:` プレフィックスの有無だけで「モバイル・タブレット / デスクトップ」を切り替えられる。

## 実装パターン

### コンテナ + 12カラムグリッド(ユーティリティクラスとして定義)

`@utility` は Tailwind の標準バリアント(`hover:` `md:` など)を外側から付けて使うことを前提にした仕組みなので、モバイル・タブレット向けの既定値だけを `@utility` に持たせ、デスクトップ側の上書きは呼び出し側で `md:` プレフィックス付きの通常クラスを重ねる。`src/index.css` に追加する例:

```css
@utility dads-container {
  width: 100%;
  margin-inline: auto;
  padding-inline: 1rem; /* モバイル・タブレットのマージン */
}

@utility dads-grid {
  display: grid;
  grid-template-columns: repeat(4, minmax(0, 1fr)); /* モバイル・タブレットは簡易グリッド */
  gap: 1rem; /* 本文文字サイズ(1rem)の等倍 */
}
```

呼び出し側で `md:` プレフィックスの標準クラスを重ねてデスクトップ用の値を上書きする:

```tsx
<div className="dads-container md:max-w-7xl md:px-6">
  <div className="dads-grid md:grid-cols-12 md:gap-8">
    {/* md:gap-8 = 2rem = 本文文字サイズ(1rem)の2倍 */}
  </div>
</div>
```

### 素の Tailwind ユーティリティだけで済ませる場合

カスタムユーティリティを増やしたくない場合は、既存クラスの組み合わせだけでも原則を再現できる。

```tsx
<div className="mx-auto max-w-7xl px-4 md:px-6">
  <div className="grid grid-cols-4 gap-4 md:grid-cols-12 md:gap-8">
    <div className="col-span-4 md:col-span-8">{/* メインカラム */}</div>
    <div className="col-span-4 md:col-span-4">{/* サイドカラム */}</div>
  </div>
</div>
```

- `gap-4`(1rem) → `md:gap-8`(2rem) がガター=文字サイズ×2 の再現。
- `grid-cols-4` → `md:grid-cols-12` がカラム数の切り替え。
- `col-span-*` は 12カラム基準で配分する(例: 8/12 + 4/12 の2カラムレイアウト)。

### 1カラムレイアウトへのフォールバック

コンテンツ幅が確保できない、あるいはシンプルな縦積みで十分なページでは `grid-cols-1`(= 1カラム代替案)のまま `md:` 切り替えを省略してよい。無理に 12カラムへ展開しない。

## チェックリスト

- [ ] ブレークポイントは独自定義せず Tailwind 既定の `md:`(768px)をそのまま使っているか。
- [ ] ガター(`gap-*`)がモバイル/デスクトップで 1rem → 2rem のように「本文文字サイズの2倍」原則に沿っているか。
- [ ] カラム数がモバイル・タブレットとデスクトップで意図的に切り替わっているか(12カラムを固定で押し付けていないか)。
- [ ] マージン・コンテナ最大幅はプロジェクト要件に基づいて明示的に決めたか(公式デフォルト値が存在しない点を踏まえた上での判断か)。
